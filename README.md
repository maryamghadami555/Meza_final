# MEZA ACCESSORY — فروشگاه و پنل مدیریت (نسخه کامل: فاز ۱ تا ۳)

شعار: **مزا، تکمیل‌کننده استایل** — فروشگاه فارسی (RTL) با طراحی آبی یخی، به‌همراه پنل مدیریت.

> این پروژه در محیطی بدون اینترنت نوشته شده، پس **هنوز نصب، build و اجرا نشده است**. بار اول که `npm install` و `npm run build` را می‌زنید، اگر خطایی دیدید متن آن را بفرستید تا رفع شود.

## ساختار پروژه
```
src/            فرانت‌اند React + Vite + TypeScript
  pages/        صفحات فروشگاه (خانه، فروشگاه، محصول، سبد، پرداخت، حساب، تماس، درباره)
  admin/        پنل مدیریت (آدرس /admin)
worker/         API با Hono (index.ts = بخش مشتری، admin.ts = پنل، lib.ts = ابزارهای مشترک)
server/         اجرای همان API روی Node برای Railway (SQLite + فایل روی Volume)
migrations/     ساختار دیتابیس (SQL)
seed.sql        داده نمونه فقط برای توسعه
admin-account.sql  ساخت حساب مدیر کل
wrangler.toml   تنظیمات Cloudflare      Dockerfile + railway.json   تنظیمات Railway
```

## امکانات
**فروشگاه:** صفحه اصلی (اسلایدر، مزیت‌ها، دسته‌ها، ویژه/جدید/پرفروش)، فروشگاه با فیلتر دسته و قیمت و موجودی، مرتب‌سازی و صفحه‌بندی، جستجو، صفحه محصول (گالری، زوم، نظرات، مرتبط)، علاقه‌مندی‌ها، سبد خرید و کد تخفیف، تسویه با **کارت‌به‌کارت و آپلود رسید**، حساب کاربری (سفارش‌ها، نشانی‌ها، پروفایل، تغییر رمز)، تماس با ما، درباره ما.

**پنل مدیریت (`/admin`):**
- داشبورد: فروش، تعداد سفارش/مشتری/محصول، سفارش‌های در جریان، رسیدهای در انتظار
- سفارش‌ها: جستجو و فیلتر، جزئیات، تغییر وضعیت، دیدن رسید، **تأیید/رد رسید**، یادداشت داخلی، تاریخچه
- محصولات: افزودن/ویرایش/حذف، چند تصویر با پیش‌نمایش، حذف و جایگزینی تصویر، تخفیف، موجودی، ویژه/پرفروش، دسته‌بندی جدید
- مشتریان: فهرست، جستجو، پروفایل، سفارش‌ها و نظرات، تعلیق/فعال‌سازی
- کارمندان: ساخت حساب، نقش آماده، تیک دسترسی‌ها، فعال/غیرفعال، لاگ فعالیت
- درگاه پرداخت: تنظیمات کارت‌به‌کارت (شماره کارت، نام صاحب کارت، بانک، توضیحات)
- تنظیمات فروشگاه (تلفن، ایمیل، نشانی) و پیام‌های فرم تماس

**نقش‌ها:** مدیر کل، مدیر، مدیر فروش، مدیر محصول، پشتیبان، مدیر سفارش — هر نقش یک مجموعه دسترسی پیش‌فرض دارد که برای هر کارمند قابل تغییر است.

## روش اول: Cloudflare (Workers + D1 + R2)
```bash
npm install
npx wrangler login
npx wrangler d1 create meza-db           # database_id خروجی را در wrangler.toml بگذارید
npx wrangler r2 bucket create meza-files
npm run db:migrate:remote
npm run admin:remote                      # ساخت حساب مدیر کل
npm run deploy                            # build + انتشار
```
**اجرای محلی:**
```bash
npm run db:migrate:local && npm run db:seed:local && npm run admin:local
npm run build
npm run dev:api     # ترمینال ۱
npm run dev         # ترمینال ۲ → http://localhost:5173  (پنل: /admin)
```

## روش دوم: Railway (railway.com)
در Railway همان کد API روی Node اجرا می‌شود؛ دیتابیس یک فایل **SQLite** و تصاویر فایل‌های روی **Volume** هستند (جایگزین D1 و R2). بنابراین فقط **یک نمونه (replica)** اجرا کنید.

1. پروژه را در GitHub بگذارید؛ در Railway: **New Project → Deploy from GitHub repo**. فایل‌های `Dockerfile` و `railway.json` خودکار خوانده می‌شوند.
2. در سرویس: **Settings → Volumes → New Volume** با Mount Path برابر `/data`.
3. در **Variables** مقدار `DATA_DIR=/data` را اضافه کنید.
4. **Settings → Networking → Generate Domain** برای گرفتن آدرس عمومی.
5. بعد از اولین Deploy موفق، حساب مدیر کل را بسازید (Railway CLI یا تب Shell):
   `npm run railway:admin`
6. مسیر سلامت `/api/health` برای Health Check تنظیم شده است. مایگریشن‌ها هنگام هر استارت خودکار اجرا می‌شوند.

اجرای محلی نسخه Node: `npm install && npm run build && npm start` (داده در `./data`).

## حساب مدیر کل
فایل `admin-account.sql` حساب مدیر کل (نام کاربری `admin_meza`) را می‌سازد. وارد شدن از آدرس `/admin` با فرم ورود انجام می‌شود. کارمندان بعدی را از بخش «کارمندان» بسازید. برای ساخت حساب مدیر با اطلاعات دلخواه: `npm run create-admin -- ایمیل "نام" "رمز"`.

## تنظیم کارت‌به‌کارت
پنل مدیریت ← **درگاه پرداخت** ← فعال‌سازی و ثبت شماره کارت، نام صاحب کارت و بانک. تا زمانی که فعال نشود، مشتری امکان ثبت سفارش ندارد.

## جریان سفارش
مشتری سفارش می‌دهد و رسید را آپلود می‌کند ← وضعیت «در انتظار تأیید پرداخت» ← مدیر رسید را تأیید یا رد می‌کند. تأیید: پرداخت‌شده و سفارش «در حال پردازش». رد: مشتری از صفحه سفارش رسید جدید می‌فرستد. بعد از تأیید، وضعیت‌ها به «ارسال شد» و «تکمیل شد» تغییر می‌کنند؛ لغو سفارش موجودی را برمی‌گرداند.

## امکانات فاز ۳
- **تیکت پشتیبانی چت‌مانند:** مشتری تیکت با موضوع، دسته‌بندی و اولویت می‌سازد، پیام متنی و تصویر می‌فرستد؛ پیام‌ها به ترتیب زمان با ساعت و وضعیت (✓ ارسال شد / ✓✓ دیده شد) نمایش داده می‌شوند. ادمین پاسخ می‌دهد، تیکت را می‌بندد، دوباره باز می‌کند و اولویت را تغییر می‌دهد. نشان (badge) پیام‌های خوانده‌نشده در منوی مشتری و سایدبار ادمین نمایش داده می‌شود و هر ۱۰ ثانیه به‌روز می‌شود.
- **نظرات مشتریان:** ثبت امتیاز ۱ تا ۵، متن و تا ۳ عکس. فقط کسی که این محصول را خریده و پرداختش تأیید شده نظر می‌دهد (نشان «خرید تأییدشده»). نظر پس از تأیید مدیر در صفحه محصول نمایش داده می‌شود و میانگین امتیاز و تعداد نظرات به‌روز می‌شود.
- **رضایت مشتریان (پنل):** درصد رضایت، میانگین امتیاز، نمودار توزیع امتیازها و روند رضایت، و صف تأیید/رد/حذف نظرات.
- **داشبورد:** نمودار فروش، سهم دسته‌ها، پرفروش‌ترین محصولات، مشتریان تازه‌عضو و آمار رضایت (نمودارها با Recharts). همه‌ی ارقام از دیتابیس خوانده می‌شود. نمودارهای زمانی در ۶ بازه‌ی ۳۰ روزه محاسبه می‌شوند (نه ماه شمسی).
- **پرداخت آنلاین (زرین‌پال):** فعال/غیرفعال، حالت آزمایشی، ثبت مرچنت‌کد، دکمه «آزمون اتصال». مشتری بعد از ثبت سفارش به درگاه می‌رود؛ بعد از بازگشت، پرداخت از سمت سرور تأیید (verify) می‌شود و سفارش «پرداخت‌شده / در حال پردازش» می‌شود. اگر پرداخت کامل نشود، از صفحه سفارش می‌تواند دوباره پرداخت کند.
- **تنوع محصول:** هر محصول چند گزینه (رنگ، سایز…) با تغییر قیمت و موجودی جداگانه دارد؛ انتخاب گزینه در صفحه محصول و سبد خرید انجام می‌شود و موجودی همان گزینه کم می‌شود.
- **فراموشی رمز:** ورود ← «رمز عبور را فراموش کرده‌اید؟» (برای مشتری و ادمین). لینک یک‌ساعته با ایمیل ارسال می‌شود.

## متغیرهای محیطی
فایل `.env.example` را ببینید. خلاصه:

| متغیر | کاربرد |
|---|---|
| `PUBLIC_URL` | آدرس عمومی سایت برای لینک ایمیل و بازگشت از درگاه |
| `SETTINGS_KEY` | لازم برای ذخیره مرچنت‌کد در تنظیمات پرداخت آنلاین |
| `RESEND_API_KEY` و `MAIL_FROM` | ارسال ایمیل بازیابی رمز (بدون آن، ایمیل ارسال نمی‌شود) |
| `DATA_DIR`، `PORT` | فقط Railway |

**Cloudflare:** `npx wrangler secret put SETTINGS_KEY` (و همین‌طور `RESEND_API_KEY`)، و `PUBLIC_URL` و `MAIL_FROM` را در بخش `[vars]` فایل `wrangler.toml` بنویسید.
**Railway:** همه را در تب Variables اضافه کنید.

## راه‌اندازی پرداخت آنلاین
1. در پنل زرین‌پال یک درگاه بسازید و مرچنت‌کد (۳۶ کاراکتری) را بگیرید؛ دامنه‌ی سایت باید در زرین‌پال ثبت و تأیید شده باشد.
2. `SETTINGS_KEY` و `PUBLIC_URL` را تنظیم کنید و سرویس را دوباره اجرا کنید.
3. پنل مدیریت ← درگاه پرداخت ← بخش «پرداخت آنلاین»: مرچنت‌کد را وارد کنید، «آزمون اتصال» را بزنید و بعد فعال کنید. برای آزمایش اول «حالت آزمایشی» را روشن کنید.
4. مبلغ‌ها در سایت به **تومان** هستند و هنگام ارسال به درگاه به ریال تبدیل می‌شوند.
سفارش آنلاینِ پرداخت‌نشده موجودی را نگه می‌دارد؛ اگر مشتری پرداخت نکرد، ادمین می‌تواند سفارش را لغو کند و موجودی برمی‌گردد.
